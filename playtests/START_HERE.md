# 新窗口从这里开始

适用于“自己玩几局，然后说感受”。先读本目录 `AGENTS.md`。无需先创建或安装 Skill。

## 1. 建立独立批次

使用 `pt-YYYYMMDD-HHMMSS-短随机后缀` 作为批次编号，创建 `playtests/batches/<批次编号>/`；目录已存在就换编号，明确续玩除外。将 `templates/` 的三个文件复制进去，填写 `brief.md`。原始存档不复制到本目录。

采用用户要求的局数；未指定时默认 1 局。未指定停止条件时，默认每局完成前24季：观察进入第25季（`game.clock.absoluteTurn >= 25`）时停止，或在 `complete / ended` 时提前停止。v18沿用人生系统，16季不再等于一代；这只是开局与疲劳体验窗口，不能代表完整人生。用户要求传承体验时，在后辈成年后安排一次季末交接，并继续观察8个完整季。另设每局 240 次已提交行动的保护上限，到达后如实记为“行动上限”，不算完成观察窗口。用户指定的目标优先，但每局仍受运行层 1500 条行动上限约束。

开始前向用户简短说明局数、决策方式和停止条件即可，不为默认值重复询问。不要为赶局数改成自动策略。

## 2. 准备一局

run ID 使用 `<批次编号>-g01`、`-g02` 等，只含字母、数字、短横线、下划线，总长不超过 80 字符。在 `brief.md` 登记 run ID 与 `artifacts/runs/<run ID>/record.json` 的关联。

先确认已有可用的 `dist/`。仅在开局准备阶段允许运行以下管理命令；将示例 run ID 换成自己的唯一编号：

```powershell
npm run lab -- new --run pt-20260913-150000-a7c2-g01 --scenario river
```

默认场景按 `river / clay-valley / woodland / dry` 逐局轮换；用户指定场景时遵循用户要求。默认不传种子，沿用入口默认初始化，不将种子加入玩家笔记或用它预测天气。这是体验采样，不据此宣称统计代表性或严格场景对照。

没有构建、开局失败或旧档不兼容时记录错误；不为试玩擅自重建、迁移或覆盖。需要开发处理时说明具体阻碍。

## 3. 模型逐步操作

```powershell
node scripts/player.mjs observe --run pt-20260913-150000-a7c2-g01
```

player 入口默认是精简观察。从可用行动中选择一个，提交时用真实的 `revision` 和 `actionId` 替换占位符：

```text
node scripts/player.mjs act --run <run ID> --revision <最新 revision> --action <当前 actionId> --reason "当前观察下选择此行动的简短理由"
```

`act` 已返回最新精简观察，可以据此做下一次决策，不必机械地再调用一次 `observe`。科技树、产品、系统或全部不可用原因用 `--section branches|industry|systems|actions-disabled`。发生错误或版本冲突时重新观察，不盲目重试动作串。完整观察使用 `--format text`。休息、疗养与换代也通过观察中提供的行动提交；依据 `game.life` 中的时间、精力和健康安排生活，不把兼容字段 `ap` 当作新版预算。四季一年，寿命潜力不可见，不得读取原档预测死亡。

只根据公开玩法说明与观察决策，不读游戏内部状态或实验策略。操作命令可以通过终端工具执行，但不能放入自动选行动的程序。用户明确要求脚本或混合模式时另建批次，写明授权、自动化范围和实际局数，不并入亲自试玩结果。

遇到困惑、惊喜、目标变化或重复劳动时，及时在 `notes.md` 记下 run ID、revision/季数、原本预期与实际反馈；不要求每一步重复抄完整观察。每局停下即更新 `brief.md`，便于新窗口续接。续玩先读批次文档，再通过 `observe` 核对真实进度。

## 4. 收尾与感受

结合最后观察填写逐局状态和 `feedback.md`。报告同时写明计划、已开始、达到窗口/目标、终局、行动上限、未完成的局数；这些停止分类互斥，不把“玩过”写成“通关”。

当前 `lab new` 会将存档代理默认登记为 `human/manual`，这不能证明实际控制方式；本批 `brief.md` 必须如实登记为“当前模型逐步决策”，或实际使用的其他方式。模型名称/版本只有已知时填写，不猜测。

身份权威保留在原始存档 `manifest`。当前玩家观察不提供完整实现身份，批次可以只引用原档并标注“身份未单独提取”；不要为了填写文档读取完整存档中的隐藏状态或填写当前构建指纹冒充运行时身份。

最终给用户先说具体感受，再说完成范围与局限，并链接本批 `feedback.md`。未完成时保留记录，明确剩余局数和原因。建议留在报告中，不自动启动研究或调整规则。

当前默认规则为0.18.0三路线分支试点：19个节点，无旧十阶主干与副本。观察 `game.economy.branchView` 选择目标、前置与渠道。实际效果分别看泵灌溉、雇员真实产出与交付、电力生产和本地负载；不要把学完节点当作经营成功。24季窗口可能只覆盖投资前段，应如实报告未完成目标。

0.22.0当前入口：学科、产品、系统三类树。学习不消耗样品；查看 `game.economy.industryView` 获取产品验证、规程、系统状态、人员预算与工资。先建设调试，再安排人员；旧自动生产/补货/销售开关不开放，不能沿用0.18脚本策略假设。试玩分别记录学习负担、验证步骤、系统劳动预留、停机原因，勿把外部供粮或本人手动经营称为无人化。

0.20补充：读取 `game.life.budget` 的逐项预留与可用预算；行动描述包含行动后预留。前代学过的节点后代仍需按前置逐个学习，但仅需1时间/1精力；教导可提前掌握。健康显示当前年龄上限，偶发缺粮先降低精力恢复，持续缺粮递进扣健康。记录脱困过程，不以是否回到100作为唯一标准。

0.21补充：`game.socialFood` 显示社会食品采购策略、共享库存/人员/运输、预计购粮与生活缺口。默认暂停持续采购；通过foodpolicy选择策略，foodbudget限制每季支出，foodreserve设置饭后储备。foodplan:on/off现在选择委托配送/本人赶集，暂停自动采购用foodpolicy:off。无需因为家庭粮为0就判定饥饿，检查资金和实际购粮可达性。

0.26补充：用 `erasettle:stage` 随时结算，不要把建井/泵当成过关。观察 `game.era.services`。农业公地采食/帮工，集镇公井，工业公共磨坊与铁/电工市场，现代配送和自来水。学堂未开放课程会写“当前社会尚未开放”。家业试炼只影响胜负。

0.25补充：观察 `game.economy.ongoing.farm`；`farmcycle` 安排持续耕作后不必每季点收获/复种。O3/O4/O5 只加一次 25% 凭证。

0.24补充：农学、组织、数学已从单链改为分叉。观察 `game.economy.branchView`：A3 肥力、A4 油料纤维不必先学 A1；O2 交付不必先学 O1；Q2 账目与 Q1 应用并列，时代生产课要 Q2。大豆/亚麻要 A4，施肥要 A3。

0.23补充（仅旧档）：当时观察 `game.era.goal`。0.26 起水井/泵不再是过关条件，以 0.26 补充为准。

0.22补充：观察 `game.era` 的当前阶段、剩余季数、社会卡、待兑回报和知识退出状态；历史阶段结算在 `eraSettlements`。社会随实际季末结算推进，退休不能加速。真实收获/加工才增加本阶段回报；阶段结束独立兑现，现代才开放最终副本。默认每阶段192季，不要求一次试玩跑完全程；报告必须注明实际覆盖窗口。数学等通用知识仍需后代低成本学习，阶段专用知识过期不生效，但已建井等资产保留。
