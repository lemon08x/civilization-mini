# 经历与传承：用实际后果反馈选择

本版在既有规则0.6.0/工程0.7.0上增加只读经历投影。没有修改src/game结算、参数、行动或GameState，故不递增规则版本、不更换存档键、不迁移历史存档，也不为展示功能重跑平衡模拟。

## 从想法到系统

1. 世界按既有规则结算，留下原始事件。
2. 经历识别器从事件提取可证实的变化：方法掌握、产品完成、设备安装、实际使用、跨代接续、传播与公共使用。
3. 玩家通过游戏提供的具体行动作出选择，承担时间、材料和机会成本；结算决定后续可做的事。
4. 每代回顾并列展示经历、行动账单、缺粮处境和仍在进行的项目。系统不把它们相加成人生分数，也不根据固定职业替玩家定义成功。

自由度必须来自规则支持的行动与后果，不要求玩家填写目标、编写角色故事或自行发明值得追求的事。游戏需要提供具体处境、明确选项和相互竞争的资源用途；不设人生总分仍然需要设计可追求的成果。经历记录是行动后的反馈，不能代替玩法。

例如现有精密零件可以出售换钱，也可投入校准设备，或留给水泵、窑炉项目；材料、学习前提和共享项目槽让这些用途产生取舍。后续新增成果也应通过实际用途、解除限制和跨代延续来成立，而不是把自由填写改成志向下拉框。

## 三种不同阶段

| 阶段 | 例子 | 不能据此断言 |
| --- | --- | --- |
| 已具备条件 | 做成泵、装上泵、留存方法、教会后辈 | 已经改善生活，后辈必然从事这一职业 |
| 已实际发生 | 用泵储水、旱季耕作用上蓄水、邻里使用公共商品 | 永久摆脱旱灾，所有成果都来自玩家 |
| 已跨代使用 | 第2代使用第1代安装且未更换的泵 | 设备所有材料都是第1代亲自生产 |

每张经历卡带有发生代/季、行动者、涉及对象，以及revision/eventIndex证据位置，可在网页展开原始事件核对。同一代同类变化只展示首次证据，不按重复次数奖励。

旱季蓄水收成必须同时有已记录天气、同一次行动中的蓄水消耗和正收成。不模拟反事实就不宣称“比没有泵时多收多少”。初始季的天气没有独立事件证据时，不猜测。公共商品使用归邻里，后辈掌握归后辈，委托经营归受托匠人；不把所有世界变化都包装成玩家功劳。

## 导出与历史数据

游戏页导出经历记录JSON，包含原规则/实现指纹和证据位置。此导出是阅读材料，不是可重放存档；原游戏存档仍从原入口导出。

根据用户纠正，已移除志向输入、保存、历史展示及导出入口。旧浏览器键`civilization-mini.life-intentions.<runId>`中的文字保留，当前游戏不再读取或写入它们。原提案保留为历史记录，纠正另记提案。此次调整仅涉及界面与说明，不改变规则版本或存档，也无需平衡模拟。

## AI和研究

`lifeChronicle()`位于研究层，仅投影已有事件，不调用语言模型。现有research:audit输出包含该经历投影，仍保留原审计的文本分析/未重放声明。诊断、叙述不写回GameState；策略输入仍只能来自observeSession。

如果之后接大模型，先给它这些结构化事实，再让它组织回顾文字。要求每个事实性句子引用证据、区分具备条件和已发生的事，禁止编造受益者、因果关系或“你的人生很成功”。不能将经历条数变成优化奖励；任何建议仍须独立假设、对照和人工决定。

## 当前边界与下一步

当前记录器只覆盖游戏已经结算的生产、用水、学习、传播和传承，不制造医疗、幸福或家庭关系事实。没有实现健康、疾病、人物关系。

下一步加入健康时，应先让疾病、治疗、休养产生可观察的过程与真实成本，再识别“某人获得治疗选择”“恢复后重新工作”等事实。生活品质也应先体现为具体限制的解除，不能先增加一个幸福分，再把所有产品变成加分道具。

验证使用定向事件投影测试、真实行动接口不变性检查、旧轨迹回归与短时网页检查；经历展示不影响物理行为，未重复运行模拟。
