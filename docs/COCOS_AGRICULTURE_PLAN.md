# Cocos 农业手机版首版重构计划

更新：2026-09-24。状态：方案待实施；本次仅提交计划文档。

## 1. 问题与目标

玩家反馈部分场景卡顿、动画观感不佳，希望将农业阶段单独拿出来，用 Cocos 面向手机重构。卡顿的具体来源尚未定位；更换引擎不能代替对结算、观察生成与渲染开销的区分。

首版目标是验证：手机上安排农事是否顺手、田院画面与反馈是否好看、真实农业流程能否稳定运行。产品主线仍是设计一个人的全年计划，通过科技提升有限时间内的生产能力，详见 [README](../README.md) 与 [全年计划实施计划](PR3_IMPLEMENTATION_PLAN.md)。

## 2. 已明确的方向与实施边界

用户已提出农业独立、面向手机、采用 Cocos 的方向，并明确要求：

- 场景布局参考对话中的竖屏农场图片：田院铺满屏幕，功能入口放在屏幕边缘的图标中。
- 场景不出现人物，不制作人物行走、农活动作、寻路或人物遮挡系统。
- 采用适合图片分层、透明素材拼接的场景表现；田地与作物能够独立变化。

竖屏、2D 轻俯视手绘风格、单人本地运行、Android 优先，是本计划的首版建议。Cocos 精确版本、首发设备与素材规格在启动实施时确定，不在此虚构兼容性结论。

“不出现人物”是场景表现要求。个人时间、知识、修行、寿命及师徒关系仍属于规则和叙事，不能据此删除。首版不安排人物立绘演出，相关状态通过文字、符号和面板表达。

本次用户授权创建分支并提交计划，允许新增本文档。根 [AGENTS.md](../AGENTS.md) 中原有桌面 Web、不引入 Cocos 的约束，已由本轮用户指示在农业手机重构方向上明确调整；本文记录这一范围，不将计划提交等同于已实施客户端或批准所有候选机制。其他项目边界继续适用，不修改 `../remake`。

## 3. 当前基础与首版范围

现行实现以 [CURRENT_GAMEPLAY_V27.md](CURRENT_GAMEPLAY_V27.md) 和代码为准。当前已有年度作物计划、农时窗口、劳动报价、冲突与缺料提示；农活仍逐项手动执行。全年自动执行、稳定循环评价、四阶段新评分尚未实现。

| 部分 | 首版计划 | 边界 |
| --- | --- | --- |
| 农田 | 选择地块、查看田况、播种、灌溉、施肥、收获 | 接现有行动与成本，不另写产量公式 |
| 农时 | 近期待办、作物窗口、日期编辑、全年概览 | 保存计划不推进时间、不预扣材料，农活逐项确认执行 |
| 场景 | 田院背景、独立地块与作物、少量环境动画 | 地块位置对应真实坐标，不预画未知探索结果 |
| 库存与补给 | 显示已有库存，接通维持农业流程所需的现有操作 | 先审计依赖，不默认扩张加工、采集或生活系统 |
| 恢复 | 接入流程必需的现有恢复入口 | 不新增恢复公式或日常行为 |
| 修行 | 接入已有课程、日课、精修与实际耗时 | 课程效果继续标注待定，不增加效率或产量倍率 |
| 农业所学 | 展示相关已有理论、实践及实际作用 | 沿用前置、耗时与生效条件 |
| 回顾 | 展示实际收获、时间及资源变化、错过的农时 | 不将库存或毛收入冒充计划产值，不生成未定义的综合分 |

完整探索剧情、复杂加工建设界面、完整师徒交接界面以及后续三个时代不作为首批迁移目标。已有农业可能依赖探索得种、水利建设、口粮、市场或人生结算；须逐项识别，决定接入哪些最小入口。不能通过隐藏按钮让游戏无法继续，也不能通过赠送资源、解锁知识或停用消耗来绕开依赖。

农业独立体验的终止条件仍待机制设计：现有阶段期限可能推动时代变化，人物寿命也可能需要交接。建议在实际边界到达前提供清晰提示，并在边界展示本次实绩；暂停或结束的具体行为必须通过核心行动落实，不能由客户端截断结算。本计划不默认改变阶段期限、跨年作物或传承规则。

## 4. 场景构图与手机操作

### 4.1 构图

- 上部：少量天空、远山与树林，承托日期、节气等简洁状态。
- 中部：农舍、田埂、水边与少量环境装饰，形成门派山居生活的背景。
- 中下部：主要可交互田地，保持足够大的可点击面积；相较参考图压缩天空比例。
- 屏幕边缘：功能图标，避免覆盖核心田块；底边避让系统手势区。

首版优先固定视角。田地超出可视区域时允许平移；是否需要缩放以真实地块布局决定，不用固定数量的装饰田替代现有地图。屏幕长宽比变化时优先裁切外围天空与草地，保留核心操作区。屏幕边缘界面独立于世界场景，并遵守安全区域。

### 4.2 功能入口

建议将农时作为最显眼的常用图标；仓库与补给、农业所学、修行、设置沿两侧与底边分布。图标配简短文字，以少量明确的入口取代常驻大型面板。天气和日期只展示当前可知信息。

点功能图标打开抽屉或覆盖面板，关闭后回到原场景位置与选中田块。点田地先显示作物、田况和可用操作，再进入农时或具体行动。界面按钮与地图触摸互斥，拖动画面结束不能误触执行农活。

### 4.3 农时与行动

1. 点田块或农时图标，查看当前待办及原因。
2. 选择作物、田块和日期；全年概览展示农忙窗口，具体编辑进入局部面板。
3. 明确显示实际时间、种子、水、材料与其他成本，以及不可执行原因。
4. 保存安排或确认执行；两种操作明确区分。
5. 核心返回结果后更新田况、日期与库存，展示一次对应反馈。

日期、多田选择等操作必须能通过点击完成，拖动仅作可选快捷方式。缺料或冲突提示连接到对应条件与处理入口。成熟、缺水等提醒集中在有关田块及农时入口，不堆叠全屏弹窗。

## 5. 图片分层与素材制作

采用“干净背景底图＋透明组件＋少量特效”。按是否需要独立变化拆图，而非把所有装饰逐件拆开。

| 层 | 内容 | 处理方式 |
| --- | --- | --- |
| 远景 | 天空、山、远林 | 合并背景；需要移动的云独立 |
| 地面 | 草地、道路、固定岸边 | 底图预留可交互田地位置 |
| 固定装饰 | 不变化的建筑、花草、围栏 | 尽可能合并，避免大量节点 |
| 独立物件 | 可升级建筑、会摆动的树 | 透明组件，统一底部锚点与比例 |
| 地块 | 空地、耕地、湿土等 | 重复使用地块组件，与稳定地块 ID 绑定 |
| 作物 | 各生长阶段、成熟与枯损 | 独立于土壤；根部锚点固定，按公开状态变化 |
| 环境与反馈 | 炊烟、水波、落种、水滴、收获 | 少量序列帧、补间或粒子 |
| 界面 | 图标、文字、面板 | 独立 UI 层，文字不烘焙进场景背景 |

制作顺序：

1. 先完成一张整体构图预览，评审田地占比、边缘图标、视角与色彩。
2. 确定地块尺寸、透视方向、光照、物件比例和锚点规范。
3. 制作没有交互物件的干净底图，并补齐被房屋、树木遮住的区域。
4. 输出真正带透明通道的物件；检查白边、原背景残色、阴影重复和边缘接缝。
5. 制作地块状态、作物生长状态和反馈素材，再进入图集与真机显示检查。

完整成图可以作为抠图来源，但被遮挡区域仍需补画。透视、光照和尺度必须统一；会移动的组件应明确阴影是随物件还是独立处理。田块和作物不能合进大背景。水渠及设施的邻接关系需要清楚可辨，表现不能改变真实拓扑。

对话中的参考图片仅用来表达构图方向，不直接成为项目素材。本次未生成或提交预览图，也未制作可用素材；先前对话中的简化界面草图不代表最新田院美术。后续生图工具与素材授权、来源记录按实际制作任务处理，不因本文自动调用付费服务。

## 6. 无人物的动画与反馈

| 行为或状态 | 画面反馈 |
| --- | --- |
| 播种完成 | 短促落种效果，地面呈现播种痕迹 |
| 灌溉完成 | 水滴落地、土色变深，然后回归静止 |
| 施肥完成 | 少量土壤反馈及一次状态提示 |
| 生长与成熟 | 作物阶段和颜色变化，少量轻摆；成熟清楚可辨 |
| 收获完成 | 作物收拢消失，显示一次真实产出，田块更新为空闲状态 |
| 修行或学习完成 | 图标或面板显示进度与真实耗时，无人物演出 |
| 环境 | 慢速云影、炊烟、水波，保持大部分画面安静 |

动画时长与游戏耗时分开，动画不承担结算。一次农活推进多少时间由规则决定；跳过反馈、切面板、切后台不能改变结果。重复反馈可以缩短或跳过，不能让玩家等待长演出才能继续操作。减少动态效果时保留文字及最终状态反馈。

## 7. Cocos 与现有规则的接入

建议使用 Cocos Creator 3.x 稳定版本与 TypeScript，先交付 Android 真机原型，浏览器用于开发预览；iOS 构建与发布环境后续确定。具体版本须验证模块加载、JSON 资源、运行时 API 和原生构建兼容性后固定。

数据流：

```text
触摸/面板选择
  → 客户端提交行动
  → 会话层串行校验并调用 game.ts transition
  → 获得新状态与事件，保存已完成结果
  → 公开观察刷新
  → Cocos 更新变化的节点并播放反馈
```

- `src/game/game.ts` 继续是唯一结算权威。Cocos 组件不直接修改日期、库存、产量或知识。
- 优先复用规则核心，先接通一条真实农业流程，再根据依赖图缩减不相关入口；不复制维护另一份农业公式。
- UI 读取公开观察与行动报价，不读取随机状态、种子或未来天气。需要新增展示数据时由观察层提供，不在客户端猜测结果。
- Cocos 生命周期、资源加载和本地存储属于客户端适配；领域层不依赖 Cocos、runtime 或 apps，不把移动端能力扩展进通用 runtime。
- 明确会话修订与串行提交边界，防止连续点击重复执行；计划编辑草稿与已提交世界状态分开。
- 存档保存逻辑结果，恢复后显示最新状态，不依赖动画是否播完。读档失败保留原档；不默认迁移 Web 旧档，也不自动提升规则版本。
- 不以 UI 隐藏代替移除系统。农业所需时间结算、生活消耗、工具耐用和其他依赖在拆分时逐项核对。

Cocos 工程目录与资源组织在实施任务中确定；本次不创建工程、模块、脚本、测试或规则版本。

## 8. 性能设计与验收建议

实施时分别观察结算、观察生成、节点更新、纹理与特效开销，避免把所有卡顿归因于渲染。真机目标建议为常见操作接近 60 帧、较重场景稳定 30 帧，并关注明显停顿与持续运行发热；这是待实测的目标，不是已达到的结论。

主要手段：

- 复用地块和作物节点，按变化更新；面板开关不重建整个农场。
- 静态素材合并，适当使用图集，避免透明大图层层覆盖。
- 按实际显示大小控制纹理尺寸；压缩格式、图集尺寸和显存预算随目标机型确定。
- 少量特效集中服务当前动作，屏外效果暂停，限制粒子数量与并发反馈。
- 面板按需刷新，避免逐帧生成行动报价、更新全部文字或遍历全部地块。
- 若结算耗时明显，先定位热点，再决定分段调度方案；不能为保持帧率跳过真实消耗或改变事件顺序。

未来验收场景包括选田与平移、打开农时、连续提交动作、收获反馈期间切页、切后台恢复、保存与重开，以及阶段边界。设备型号、耗时和资源开销在实际验收时观察，不编造数据。

本次为纯文档提交，不构建、不测试、不模拟。后续执行测试或试玩仍遵守用户当次指示与仓库约定，不新增测试文件或试玩记录。

## 9. 分阶段交付

| 阶段 | 交付内容 | 完成标准 |
| --- | --- | --- |
| A：构图与依赖确认 | 一张无人物竖屏预览、图标布局、农业依赖与边界梳理 | 田地和边缘入口清楚；素材可拆分；不会因缺少必要入口阻断流程 |
| B：真实行动贯通 | Cocos 加载现有规则、新局、选田、报价、一次真实农活与保存 | 手机端结算和现有核心一致，刷新与重开不重复结算 |
| C：农业表现闭环 | 分层田院、作物状态、农时编辑、照料与收获反馈 | 能完成一条真实种植流程，操作不被动画阻塞，无人物节点 |
| D：必要配套与真机交付 | 库存补给、必要恢复、农业所学、基础修行、生命周期处理 | 能持续进行农业操作；不可用条件可理解；切后台与重开状态正确 |

所有阶段均待实施。先用一条流程确定交互和素材标准，再扩展已选定范围。首版不以完成全部农业目录或后续时代作为交付条件。

## 10. 后续机制工作与待定事项

以下事项继续沿 [全年计划实施计划](PR3_IMPLEMENTATION_PLAN.md) 单独推进，不能在客户端迁移中隐式决定：

- 全年计划的年度边界、行为粒度、条件安排与异常处理，以及真实自动执行。
- 农业独立体验在阶段结束、人物寿命与交接时的处理。
- 产值折算、库存与采购扣算、跨年作物、稳定循环判定与四阶段权重。
- 修行对全局行动的具体效果、维护收益与效率公式。
- 哪些候选辅助行为值得加入年度安排，如何形成时间与收益取舍。

首次实施前需明确的技术与内容选择：目标 Android 设备、Cocos 精确版本、首批作物与必要设施范围、工程位置及素材规格。首版不提供联网排行榜、离线挂机收益或后台自动执行承诺。
