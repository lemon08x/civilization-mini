## 1. 基线、目标与交付边界

本计划基于 v0.27.0（提交 `7870c62`）的架构审查。本地与远端 main 已同步到该提交，包含 `313630f`、`7870c62` 的功能更新。本 PR 分支已基于最新 main 更新。

后续实施以该基线为起点；若 main 继续变化，应在实际目标基线上重新核对文件、接口及依赖。功能基线属于 main。全部阶段在本 PR 内按原子提交实施，供一次验收。

目标：

- 降低模型每次行动的观察阅读量和重复工具调用，保留最新观察下的逐步决策。
- 让观察呈现、农业、加工、劳动预算、存档等职责可以局部修改和验证。
- 保留唯一结算入口、真实因果顺序、可重放记录和严格存档身份检查。
- 逐步消除领域内部循环依赖，并用自动检查防止回退。

**本 PR 实施阶段 A–D。** 第一笔提交为计划；随后提交按原子序列落地精简观察、观察契约与宿主配置、库存/劳动/农业加工拆分、季末阶段显式化。阶段 E 先做同请求观察复用与耗时记录；会话缓存仅在测量证明必要时才改。不将精简观察阻塞在领域拆分之后。

不包含规则平衡调整、新玩法、脚本代玩、付费模型调用、常驻 AI 循环、微服务、ECS、插件容器或全局事件总线。不修改 ../remake，不删除或改写历史实验、存档和用户修改。阶段 A 不修改 `src/game`；B–D 改领域实现会改变构建指纹，旧档按原身份验证，不伪造新指纹。

## 2. 审查证据与问题

### 2.1 外层边界已有基础

`game` 负责确定性规则；`runtime` 负责命令、会话、记录和重放；`agents` 根据观察选择行动；`research` 推导指标与组织实验；CLI、网页负责组合。保留此分层。现有依赖测试保护领域层不依赖运行层、策略、研究和应用，但没有充分保护领域内部边界，也尚未约束呈现层。

### 2.2 领域内部职责交叠

v0.27 静态导入扫描发现一个包含 11 个模块的循环依赖组：`economy`、`industry`、`social-food`、`shop`、`branches`、`industry-products`、`operations`、`workshop`、`tower`、`modern`、`expedition`。这是源码导入层面的结果，不代表每次调用都发生递归。

`systems/economy.ts` 同时负责库存、设备、农事、加工、员工、季末结算和观察组装。工业依赖其中的基础操作，经济又调用工业结算。工业和供粮之间也通过劳动计算形成相互依赖。

`actions/definition.ts` 的通用构造逻辑直接理解科技分支、采购与工业预留，并对部分行动调用执行回调，在状态副本上计算行动后预算；还依赖行动 ID 和中文说明进行特殊处理。业务规则持续进入通用层。

多数系统接收完整可写 `GameState`。虽然唯一入口冻结输入输出，模块内部仍缺少明确的状态写入归属。`time.ts` 的季末调用顺序承载真实因果关系，应显式表达，不能任意重排。

### 2.3 观察、状态与身份绑定

`economyView()` 复制整个经济子状态，再附加各类视图、参数和静态目录；`SessionObservation` 从 `observeSession()` 返回值推导类型。内部结构变化因此容易扩散到网页、模型和策略。

`textObservation()` 仍输出完整可见状态及全部不可用行动，不是真正摘要。一次只读观察测量（run `pt-20260916-121652-k3q7-g01`，revision 12、第 5 季）得到：JSON 270,696 字符、10,101 行，381 个行动中 61 个可用；观察文本文件 99,176 字符、3,694 行；单次 observe 约 365 毫秒。这只是该次短局样本，文本文件与命令读取也不是原子采样，不推断所有局面或端到端模型耗时。

实现指纹只覆盖编译后的 `src/game`。本 PR 的呈现模块放在 `src/game` 外，避免只调整观察就使存档身份不匹配。阶段 B 若把投影移出 `src/game`，必须另附新的构建身份与旧档处理说明，不能伪装成格式修正。

仓库已有 `scripts/observe-compact.mjs`，它再调一次完整 JSON observe，且按不存在的 `game.resources` 等字段猜测摘要。本 PR 用正式呈现模块替换这条旁路，避免两套精简逻辑。

### 2.4 运行与入口耦合

CLI 每次启动校验构建身份，`FileRunStore.load()` 从头重放，submit 再经 load 后提交，并保存完整历史备份。长局重复成本值得测量，但短局数据尚不能证明它是主要瓶颈。

`apps/board/server.ts` 引用 `apps/cli/context.ts` 加载宿主配置与身份。CLI 同时组合玩家操作和研究命令。后续 PR 应提取共享的宿主配置加载模块，而不是让一个应用依赖另一个应用的内部模块。

## 3. 目标职责与依赖方向

保留单体工程和 `src/game/game.ts` 唯一结算权威。按业务能力组织内部模块，模块内部聚合自己的类型、规则计算、行动实现和测试；通过明确的公共出口被其他模块调用。目录迁移不是目标，职责和依赖变化才是验收依据。

| 职责 | 拥有的状态与规则 | 对外提供 |
| --- | --- | --- |
| 库存与设备 | 物资数量、设备耐用及占用的基础操作 | 查询、增减与使用结果 |
| 农业 | 田地、生长、播种收获、持续耕作 | 行动、任务需求、结算结果 |
| 加工 | 配方、投入、加工项目与产出 | 检查、启动、推进与完成 |
| 劳动预算 | 本人与员工的可用时间、精力及任务分配规则 | 需求汇总、预算与冲突 |
| 市场与物流 | 报价、采购、订单、到货 | 采购需求、交易与到货结果 |
| 知识与传承 | 学习条件、个人掌握、家族记录 | 能力查询与学习、传承操作 |
| 阶段编排 | 跨系统的明确调用顺序 | 一次行动或一次季末转换 |
| 公开观察 | 玩家可见字段与合法行动报价 | 显式的只读公开契约 |
| 呈现适配 | AI 摘要、网页面板、文本与 JSON | 不参与结算的输出 |
| 运行与存储 | 命令顺序、验证、保存、恢复 | 会话服务、重放器和存储适配器 |

基础库存等模块不反向依赖农业、工业或商城。跨系统协调放在明确的编排层，不能通过新增一个包揽所有能力的公共工具模块解决循环依赖。

本 PR 只新增「呈现适配」中的 AI 摘要，输入限于已有 `SessionObservation`。

## 4. 分阶段实施

阶段划分对应本 PR 内的原子提交，而不是多个 PR。

### 阶段 A：先独立改善 AI 观察与操作流程

实施内容：

1. 在 `src/game` 外新增摘要转换模块，仅接收 `SessionObservation`，不得接收 Session、GameState 或原始存档。初期使用现有完整公开观察作为输入，不改结算或存档格式。
2. 添加显式的精简输出选项，供试玩入口默认采用；保留已有 JSON/text 格式行为，避免直接破坏消费者。
3. 摘要包含 run ID、revision、状态、季数、资源、时间精力预算、当前阶段与任务、最新事件及可用行动的 ID 和关键报价。材料成本、行动后劳动预留和紧急阻碍不能为缩短文本而隐去。
4. 提供从同一公开观察获取分区详情的方式，用于科技、产品、系统、不可用行动原因。静态目录按需读取；摘要应明确详情入口，不用裁掉字符串代替语义摘要。
5. `act` 返回可供下一步决策的最新摘要，成功后不再要求重复读取观察文件或调用 observe。异常、冲突、恢复试玩或文件更新警告时重新观察。
6. 更新 AI_PLAYER、试玩入口和网页接入说明，消除过期版本叠加及重复读取指引。仅关键发现写笔记；行动理由保持简短。
7. 删除或改为薄封装 `scripts/observe-compact.mjs`，避免与正式 `--format compact` 并存。

验收：现有 `json`/`text` 保持兼容；公开信息边界不扩大；摘要 revision 与动作结果一致；关键报价和风险没有丢失；同一公开观察样本的输出字符数明显下降，记录实测比例而不预先承诺倍数。摘要转换不会减少完整观察生成本身的计算成本，应明确此阶段收益主要是传输和阅读量。

### 阶段 B：收紧观察契约与应用边界

1. 为公开观察定义显式只读契约，逐块替换内部状态整体展开；先兼容已有字段，再评估弃用。
2. 将公开投影、按用途选择信息、文本排版分开。查询不选择行动，也不能根据隐藏状态筛选“推荐”动作。
3. 分离静态知识目录与动态状态，提供目录版本及按需获取方式；缓存不能跨错误规则身份复用。
4. 逐步从结算模块移出视图组装，避免规则实现为了呈现反向依赖其他业务系统。
5. 提取 board 与 CLI 共用的宿主配置/身份加载模块；玩家命令与研究命令分别组织，保留明确组合入口。

验收：改 AI 文本无需改网页或结算模块；新增内部状态字段不自动成为公开接口；网页和策略依赖公开契约；共享启动配置不再借道另一个应用。

迁移注意：将已有文件移出 `src/game` 会改变现行实现指纹。此步骤需安排新的构建身份与旧档处理说明，不把它伪装成已有存档可直接继续使用的格式修正。

### 阶段 C：打断经济、工业与供粮的依赖环

1. 先抽取库存和设备的基础查询/操作，保持已有事件、状态结果与调用顺序。
2. 从 economy 拆出农业与加工职责，逐步减少跨模块直接写状态；不要求一次改写持久化状态布局。
3. 工业、持续农事、采购分别提供任务需求，由劳动预算模块统一计算；各业务不再相互调用预算实现。
4. 行动报价与实际结算共享预算计算。需要行动后报价时采用显式纯计算或隔离预演接口，避免通用构造函数任意执行业务回调。
5. 通用行动层仅组合结构化成本、条件与效果。阻碍使用稳定代码及参数，中文说明在呈现处生成，不再靠文本内容判断规则或行动可见性。

验收：上述循环依赖组逐步缩小；新基础模块不依赖上层业务；农事、加工、供粮与工业组合下的预算报价和实际扣费一致；不会漏掉预留或重复收费。

### 阶段 D：显式化季末流程、状态归属与历史组合

1. 记录当前季末的实际阶段及读写关系，再提取有名字的阶段函数，保持原有先后顺序。
2. 明确生产、采购、消费、损耗、生命与时代结算之间的数据传递；阶段结果与审计事件分工清晰，减少对同一个可变事件数组的隐式反复扫描。
3. 为子系统逐步收窄可写上下文；根状态由唯一结算入口持有，跨模块效果通过明确接口或编排应用。
4. 将历史规则与当前规则的组合选择收敛到明确的初始化/能力配置位置，减少到处判断可选子状态；保留旧规则、冻结基准与可复现路径。

验收：能从阶段编排直接读出因果顺序；局部模块无法随意写入无关子状态；重构不改变天气随机调用顺序、事件顺序、消耗、产出及传承结果。发现行为差异应停止当作等价重构，单独登记规则变更。

当前 `newSeason` / `finishSeason` 的既有顺序是冻结参考，抽函数时按源码核对，不能臆造重排。

### 阶段 E：按证据优化会话、重放与身份边界

此阶段以最小性能测量证明必要性后实施，不作为 A 阶段前提。

1. 区分完整重放验证器、已验证会话服务和文件存储适配器；保留 commandId 幂等、expectedRevision 校验、独占写入、原子保存及历史保护。
2. 若采用有生命周期的会话复用，明确存档外部变化检测、重启恢复、冲突处理和失效条件。跨进程不能仅凭 revision 假定内容未变；缓存和快照不能绕过验证。
3. 同一请求复用已生成的公开观察，减少重复投影；测量启动、身份校验、重放、观察生成、保存和输出各阶段耗时。
4. 设计规则版本、确定性实现身份、观察契约版本与呈现版本的职责。只有实际分离了代码依赖，才能考虑缩小规则指纹范围；保留所有影响结算的传递依赖。
5. 新身份方案必须有显式记录格式/兼容说明。旧记录继续按原方案验证，不伪造新指纹，不默认迁移或覆盖旧档。

验收：长局性能收益有证据；篡改、过期命令、重复命令、并发和重启恢复保护不退化；呈现变更与结算身份的关系可以清楚解释。

## 5. 本 PR 冻结范围与原子提交

本 PR 名称：架构内聚度与 AI 试玩优化。包含阶段 A–D 的实现，以及阶段 E 中已有证据支持的同请求观察复用。

### 5.1 冻结接口

新增 `src/present/compact-observation.ts`，只依赖 `SessionObservation` 类型，不导入 `GameState`、`Session`、`RunRecord` 或 `src/game/**`。

```ts
export type CompactSection =
  | 'branches' | 'industry' | 'systems' | 'social-food'
  | 'era' | 'catalog' | 'actions-disabled';

export function compactObservation(
  observation: SessionObservation,
  extras?: { receipt?: { duplicate: boolean; revision: number } },
): CompactObservation;

export function formatCompactObservation(compact: CompactObservation): string;
export function observationSection(
  observation: SessionObservation,
  section: CompactSection,
): string;
```

`CompactObservation` 必须包含：`runId`、`revision`、`status`、时钟（绝对季、年、季节名）、钱/家庭粮/可食总量/仓储、时间精力预算（剩余、预留、行动后可用）、健康与困境（若公开观察已有）、当前阶段与进行中任务的短描述、最近事件、全部**可用**行动的 ID 与关键报价、紧急阻碍、分区详情入口。

关键报价不得省略：时间、精力、钱、粮、材料成本、行动说明中已有的行动后劳动预留。紧急阻碍取自不可用行动，至少覆盖时间不足、精力不足、口粮/食物不足、钱财不足、健康、困境、劳动预留冲突，以及休息、疗养、季末、农事、购粮一类生活/生产入口被禁用的原因。不得把全部不可用行动写入摘要。

CLI 增加：

- `--format compact`：stdout 为精简文本。`lab` 默认仍为 `json`；`scripts/player.mjs` 未传 `--format` 时默认 `compact`。
- `observe --section <CompactSection>`：从同一次公开观察打印分区详情。与 `--format` 同时出现时，section 优先。
- 成功 `act` 的 compact 输出必须带新 revision；json 路径继续附带 `receipt`。
- `observation.md`：当本次命令为 `text` 或 `compact` 时，文件内容与 stdout 使用同一套转换；`json` 命令仍按现有行为写入完整文本观察，不改历史消费者。

摘要中的详情入口写成可执行命令，例如：

```text
node scripts/player.mjs observe --run <runId> --section branches
```

不得靠截断 JSON 冒充分区摘要。

## 7. 验证策略

- 本计划属于纯文档，不运行构建、测试或模拟。
- 实现期间仅运行相关测试；一轮代码改动收尾统一运行一次 npm test，保留 8 条旧轨迹、349 个状态基准及接口保护检查。绝不修改 legacy-v1.json 迁就实现。
- 观察测试覆盖字段选择、关键报价、revision、兼容格式和敏感字段边界；不为低影响排版写镜像测试。对 `formatCompactObservation` 只抽查必有段落和行动 ID，不把全文当快照。
- 预算与阶段拆分测试覆盖实际交叉因果，例如农事改变供水需求、采购改变劳动预留、员工与本人预算、季末消费及交接。这些测试属于后续 PR。
- 新增内部依赖检查，优先使用 TypeScript 导入解析，区分类型和值依赖；明确允许的模块出口。对现有循环建立基线，只允许收缩、不允许扩张，最终删除对应豁免。本 PR 至少禁止 `src/game` / `src/runtime` 依赖 `src/present`，且 `src/present` 不得导入领域状态或存档类型。
- 涉及界面行为或观察交互时做一次短时试玩，模型依最新观察逐步行动，按独立批次保存；不以自动脚本替代体验。
- 纯整理或格式变化不重跑模拟。只有行为变化、失败或明确研究问题需要时，运行最小受影响场景/策略的固定种子对照，不默认扩大到全批。
- 性能先使用合法公开观察样本测输出体积，并在相同 revision、相同构建下记录只读命令耗时。端到端模型时间单独计量，不从文件大小推算实际加速倍数。建议复用 `pt-20260916-121652-k3q7-g01` revision 12 作为体积对照样本；该存档若已不可重放，改用同规则新开短局的一次只读观察，并写明 run/revision。
- 原实验与报告保留实际运行身份及结论范围，不为追齐最终指纹重跑实验或刷新报告。

## 8. 风险、停止条件与回退

主要风险是报价与结算分叉、阶段顺序改变、随机调用顺序漂移、公开摘要遗漏关键信息、旧档身份不匹配和缓存失效遗漏。

本 PR 的具体风险：compact 漏掉材料或劳动预留导致误决策；`--section` 拼出公开观察中不存在的字段；player 默认 compact 让仍依赖完整 `observation.md` 的流程漏读。回退入口是 `--format text` 与完整 JSON。发现摘要与公开观察不一致时停止当作完成，补测试后再继续。

每次职责迁移先维持现有行为和持久化布局；发现差异先定位，不能通过重录基准或迁移原档掩盖。规则行为修改另附规则版本与迁移方案。无行为变化的实现重构也必须如实保留新旧实现身份，不声称旧档自动兼容。

摘要模式保留完整观察作为回退入口。其余改动按独立提交回退；回退代码不会恢复被新版推进的存档，相关运行应使用独立 run ID 并保留匹配构建。历史文件与现有用户试玩不接管、不覆盖。
