# 跨领域知识与模拟研究框架

框架版本 0.1.1，基于现行规则 0.4.0。32 个节点覆盖农业、工业、科学、医学、商业组织、哲学制度、信息文化；12 个现行节点与规则核对，20 个候选尚未接入行动与结算。当前阶段完成机器可读研究框架与诊断入口，不宣称已实现工业时代。

本次不改变领域实现、规则或存档格式，不需要迁移。旧档继续使用原指纹和原重放要求。未来节点进入游戏时另增规则版本，写出原料、行动、事件、观察与跨代状态的迁移方案；禁止给历史存档换指纹。

## 节点契约

`experiments/frameworks/knowledge.v1.json` 是研究配置，不是规则覆盖文件。每个节点包含世界条件、当地接触、个人实践、家庭应用、传承、成本、待研究问题；关系分 required、alternative、helpful、debates。现行节点的必要/替代/帮助关系必须与规则一致；候选前置是待检验设计，不是已考证的历史结论。框架保留 12 个现行节点，不自动将规划导入游戏。

必要和替代依赖不能形成解锁环；促进与思想讨论允许双向关系。思想传统并存，不能通过单一等级决定优劣。文字、教育、工业、思想都要通过真实行动和条件产生收益；世界已有不等于当地可接触，更不等于个人掌握或家庭能应用。

下一批实现优先两条切片：木作—测量—机械（核算建设、维护后的净行动变化）；计算—记账—文字（核算信息与记录如何影响经营和跨代）。伦理与协商先明确有成本的组织选择，再接入事件。蒸汽、电气和医学作为后续候选，不能仅添加学习按钮和永久收益加成。现有委托只是契约合作的一种有限原型，尚无广义履约、债务制度。

## 有限轮次的研究闭环

1. 研究代理读取框架的 questions 和已有提案，选一个具体问题，先记录假设、反证条件、成功指标、不能恶化的指标和停止条件。
2. 检查节点是否已接入结算、策略是否会尝试相关行动。未实现则做机制版本开发；未尝试则先补策略，不能盲目调数值。
3. 用同规则/实现、场景、种子、策略及行动预算进行小批量配对；机制开关或策略差异必须明确记录。一次参数候选只改变一个主要因素，另存 experiments/，不改默认 rulesets/。
4. 玩家只收 observeSession()；通过同一行动接口提交。模拟结束保存清单与逐局事件。运行失败保留已有文件，不能把不完整批次报告成完整成功。
5. 对相关逐局文件运行诊断。研究代理查看原文件、revision 和 eventIndex，再提出机制、参数、策略或界面问题；发现信号不是自动接受理由。
6. 将独立提案保存至 experiments/proposals/，附原实验、前后差异、失败案例、副作用和决定。接受机制后才更新实际生效版本；无改善就记录并停止该方向，不能无期限降成本。

这些步骤可由后续研究代理重复执行，但当前没有后台模型循环，没有真实模型自动提案，也不会自动采纳。每轮预算沿用项目约定；本工具最多检查 8 个文件，不启动模拟、不调用 API。脚本控制器明确称为脚本基线。

## 诊断命令

构建后执行：

```powershell
npm run research:audit -- artifacts/experiments/<实验目录>/runs/<逐局文件>.json
```

也支持专项实验根目录的逐局 JSON，或 artifacts/runs 下 record.json。必须是逐局记录，不能把 metrics.json 当作轨迹。输出追加到 experiments/audits/audit-*.json，独占创建，不覆盖原档；任一输入读取失败则不生成本批报告。审阅页「跨领域框架与研究问题」刷新可查看。

每份诊断保存原文件 SHA-256、原声明规则/实现/控制器、框架与分析器指纹及事件位置。只分析已有事件，不重放、不校验原哈希链，不冒充新实验；引用前需依据任务要求另做对应版本的重放校验。历史版本分开呈现，不自动做跨版本数值比较。

当前信号：

| 信号 | 含义与限制 |
| --- | --- |
| learning-unfinished | 同一人物学习后，窗口内未见掌握；不直接归因学习成本 |
| workshop-unused | 设施建成后未见同类批量完工或委托开工；可能只是窗口不足或未选择生产 |
| contract-waiting | 保留具体等待原因，检查供应、订单与工序 |
| food-shortfall | 标出生活代价，避免只优化钱财 |
| legacy-handoff | 提醒检查后代用途；交接本身不证明传承有效 |
| node-unvisited | 没有节点相关事件，仅表示覆盖缺口，不能证明不可达 |

诊断输出的 researchQuestions 是研究队列匹配，不是结论或自动生成的修改建议。没有证据的覆盖缺口使用空 evidence；其余位置的 eventIndex 从 0 开始，revision 使用原记录值。新机制实现时增加专用事件和相应诊断；不向 GameState 写研究统计，不让大模型文案决定结果。

## 多维评估

同时检查生活缺口、总行动成本、实际产品与用途、跨代使用、资源守恒、可行路线以及策略覆盖。现有指标不能衡量的思想、卫生、信息价值必须先定义可观察结果；不生成一个包办所有目标的文明总分。单种子结果只说明局部现象，脚本偏好不代表所有玩家行为。
